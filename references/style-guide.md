# 像素风 × CRT 视觉规范

这份规范服务于 `pixel-crt-anim`：目标是让同一套代码在桌面和手机上都有“像旧显示器里跑出来的像素动画”的质感。原则只有一句：**先画好一个低分辨率的画面，再让屏幕把它弄脏一点。**

## 1. 画幅与像素网格

| 项目 | 推荐值 | 说明 |
| --- | --- | --- |
| 展示画幅 | 720 × 1280（9:16） | 竖屏，适合手机与作品集封面 |
| 逻辑画布 | 360 × 640 | 每个逻辑像素 = 2 个展示像素，像素颗粒清楚 |
| 更粗的像素 | 320 × 568 | 适合 8-bit 极简风，但文字可读性下降 |
| 字体栅格 | 5 × 7 | 大写英文与数字，1px 间隔 |
| 安全边距 | 左右 20–24px，上下 20–28px | 按逻辑像素计，保证缩放后不贴边 |
| 主体占比 | 画面高度的 40%–65% | 小于 35% 会像背景装饰 |

不要用 720 × 1280 的逻辑画布直接画 1px 细节；那会得到“分辨率很高的矢量图”，不是像素画。先决定一个低分辨率网格，所有关键轮廓尽量落在整数坐标上。

### 像素化的三件事

1. **轮廓有阶梯**：斜线呈锯齿，不追求平滑。
2. **颜色有限**：单个画面 10–16 个主色即可，靠明度分层。
3. **过渡用抖动**：两个颜色交界处用棋盘格或条带，而不是大面积渐变。

## 2. 常用调色板

颜色是氛围的主要来源。每次只选一个主色系、一个辅助色、一个高光色，再加深色轮廓。

### 配色纪律

- 亮色面积不超过画面的 15%，否则没有“屏幕发光”的感觉。
- 背景永远比主体暗 20%–35%，主体边缘用深色描边拉开。
- 金属不要只用一种黄色：暗部、本色、高光至少三层。
- 同屏不要同时出现纯红、纯绿、纯蓝的高饱和大面积色块，容易廉价。
- CRT 的荧光感来自“暗底 + 少量高亮 + 轻微色差”，不是把所有颜色调亮。

## 3. 构图

### 竖屏三段式

```text
┌────────────────────┐
│ 顶部 HUD / 标题     │  0–18%
│                    │
│      主体区域       │  18%–72%
│                    │
│ 地面 / 前景 / 数据  │  72%–100%
└────────────────────┘
```

- 顶部放 1 个主标题和 1 个状态标签，不要堆满。
- 主体放在视觉中心略偏上，底部留出地面或反光。
- 底部 HUD 用两行以内，不要把说明文字写成段落。
- 用十字标线、轨道环、刻度线制造“仪表盘”感，但透明度控制在 0.08–0.25。

### 主体清晰度检查

把画面缩小到 320px 宽，眯眼观察：

- 能否在 1 秒内说出主体是什么？
- 主体是否和背景有明度差？
- 轮廓是否有至少一处独特特征（长喙、天线、齿轮、尾巴）？
- 去掉所有文字后，画面是否仍然成立？

如果答案是否定的，先改剪影，不要加特效。

## 4. 像素字体

### 原则

- 只使用内置 5×7 点阵字体，或系统等宽字体；不要外链字体。
- 字号只取 1×、2×、3× 三档，避免半像素缩放。
- 关键信息（标题、WING、CORE）至少 2×，即逻辑高度 14px；手机 360px 宽时可读。
- 1× 字号只用于装饰性微文本，例如坐标、版本号、刻度标签。
- 全大写更稳定；字距至少 1 个逻辑像素。
- 中文不要用 5×7 点阵硬画，会缺字。中文放 `<title>`、`aria-label`、README；画面内使用英文短句。

### 点阵字绘制

```js
// 每个字符用 7 行 5 列字符串描述，1 表示亮点
const FONT = {
  A: ['01110', '10001', '10001', '11111', '10001', '10001', '10001']
};

function drawText(text, x, y, scale, color) {
  for (let i = 0; i < text.length; i++) {
    const glyph = FONT[text[i]];
    if (!glyph) continue;
    for (let row = 0; row < 7; row++) {
      for (let col = 0; col < 5; col++) {
        if (glyph[row][col] === '1') {
          ctx.fillStyle = color;
          ctx.fillRect(x + (i * 6 + col) * scale, y + row * scale, scale, scale);
        }
      }
    }
  }
}
```

### 排版层级

| 层级 | 尺寸 | 用途 |
| --- | --- | --- |
| 主标题 | 3×（21px 逻辑高） | 作品名，最多两行 |
| 关键数据 | 2×（14px） | WING / CORE / 分数 |
| 标签 | 1×（7px） | 编号、单位、装饰刻度 |

## 5. CRT 效果配方

CRT 效果分四层，全部用 CSS 叠加，不参与 Canvas 绘制，方便统一调节。

### 5.1 扫描线

```css
.scanlines {
  position: absolute;
  inset: 0;
  background: repeating-linear-gradient(
    to bottom,
    rgba(0, 0, 0, 0.26) 0,
    rgba(0, 0, 0, 0.26) 1px,
    transparent 1px,
    transparent 3px
  );
  mix-blend-mode: multiply;
  opacity: 0.7;
  pointer-events: none;
}
```

- 1px 暗线 + 2px 透明，形成 3px 周期。
- 文字区域可降低到 0.45–0.6，避免笔画被切断。
- 展示尺寸小于 360px 宽时，改为 4px 周期，防止摩尔纹。

### 5.2 荫罩 / RGB 条纹

```css
.mask {
  position: absolute;
  inset: 0;
  background: repeating-linear-gradient(
    90deg,
    rgba(255, 70, 100, 0.05) 0 1px,
    rgba(80, 255, 190, 0.035) 1px 2px,
    rgba(90, 140, 255, 0.05) 2px 3px
  );
  mix-blend-mode: screen;
  opacity: 0.6;
  pointer-events: none;
}
```

透明度必须低。高于 0.1 会明显偏色，像素画会显脏。

### 5.3 暗角与反光

```css
.vignette {
  position: absolute;
  inset: -2px;
  background: radial-gradient(
    ellipse at 50% 44%,
    transparent 42%,
    rgba(0, 0, 0, 0.28) 70%,
    rgba(0, 0, 0, 0.78) 100%
  );
  pointer-events: none;
}

.glare {
  position: absolute;
  inset: 0;
  background: linear-gradient(
    112deg,
    rgba(255, 255, 255, 0.07),
    transparent 28%,
    transparent 70%,
    rgba(255, 255, 255, 0.025)
  );
  pointer-events: none;
}
```

### 5.4 缓慢扫描带

一条高度 12%–16% 的柔光横带，8–12 秒从下往上扫一次：

```css
.sweep {
  position: absolute;
  left: 0;
  width: 100%;
  height: 14%;
  background: linear-gradient(
    to bottom,
    transparent,
    rgba(155, 255, 230, 0.05),
    transparent
  );
  animation: sweep 9s linear infinite;
}

@keyframes sweep {
  from { transform: translateY(760%); }
  to   { transform: translateY(-120%); }
}
```

### 5.5 开机与故障

- 开机：拿一条 2px 水平亮线，从中间向上下展开到全屏，持续 0.6–0.9 秒；同时做一次很轻的白闪（不超过 0.18 透明度）。
- 水平错位：每隔 4–9 秒，让一条 8–20px 高的横条左右偏移 1–3px，持续 2–4 帧。
- 色差：只对标题或局部做 RGB 分离，偏移 1–2px；不要整屏持续分离。
- 闪烁：透明度在 0.94–1.0 之间慢速变化，周期 4–7 秒；禁止每帧明暗跳动。
- 故障是“标点符号”，一屏同时出现的故障元素不要超过 2 个。

## 6. 抖动与过渡

像素画没有平滑渐变，用图案模拟过渡。

### 棋盘抖动

```js
// 两种颜色的棋盘格交界，用于球形或云层明暗过渡
for (let y = 0; y < h; y++) {
  for (let x = 0; x < w; x++) {
    const checker = (x + y) % 2 === 0;
    ctx.fillStyle = checker ? colorA : colorB;
    ctx.fillRect(x, y, 1, 1);
  }
}
```

### 条带抖动

- 球体：按纬度每 2–4px 换一档颜色，而不是渐变。
- 金属：暗部、本色、亮部三条硬边。
- 光晕：由内向外用 4–6 层低透明度同心形状，边缘保持硬阶梯。
- 阴影：用深色 + 棋盘格半透明覆盖，不用模糊阴影。

## 7. 动画语言

### 时间结构

| 层 | 周期 | 例子 |
| --- | --- | --- |
| 主循环 | 1.5–4 秒 | 悬停、呼吸、旋转、心跳 |
| 次循环 | 0.4–1.2 秒 | 翅膀、指示灯、扫描线 |
| 环境循环 | 6–20 秒 | 星云漂移、太阳升起、扫描带 |
| 一次性事件 | 1–2 秒 | 开机、彩条切换、故障 |

每个运动使用不同频率，避免整屏同频。例如：

```js
const bob = Math.sin(t * 1.8) * 2;
const flap = Math.sin(t * 20);
const glow = 0.5 + 0.5 * Math.sin(t * 3.1);
```

### 让运动“有重量”

- 位置：加 2–3 个不同频率的正弦叠加以获得不完全规则的浮动。
- 旋转：齿轮用恒定慢速，眼球用低频左右扫视。
- 出现：不要突然从 0 到 1，给 0.2–0.4 秒的淡入或从下方 4–8px 滑入。
- 循环：首尾状态要能接上；用 `sin/cos` 天然循环，或让粒子在边界处淡出。
- 步进感：像素动画不必 60fps 更新所有元素；翅膀、粒子可以量化到 24fps，背景保持连续运动。

### 常见动作配方

- **机械悬停**：`y += sin(t * 1.7) * 2 + sin(t * 0.7) * 1`，再叠 1px 的水平漂移。
- **翅膀**：两根从肩部出发的叶片，角度在 `-2.2 ± 0.7rad` 摆动；在身后画 2–3 个半透明残影。
- **呼吸光**：中心亮度 `0.55 + 0.45 * sin(t * 3)`，外圈半径同步变化 1–2px。
- **齿轮**：齿点按角度旋转，中心保持不动；不需要画出完整齿形。
- **数据变化**：HUD 数值用 `sin` 做 ±1 的微变化，不要真的每帧随机跳。
- **粒子**：用固定公式给每个粒子分配 x、y、速度、相位，通过取模循环。

## 8. 主体设计：机械生物

机械生物比纯几何更容易做出记忆点。推荐结构：

1. **剪影**：先确定一个能认出的外轮廓（长喙、翅膀、尾巴、天线）。
2. **基础体块**：椭圆或方块的胸腔、头部、尾部。
3. **机械层**：黄铜面板、铆钉、外露齿轮、管线。
4. **生命层**：发光的眼睛、能量核心、呼吸灯。
5. **环境互动**：悬停气流、花蜜粒子、轨道标线。

材质画法：

- 黄铜：`#7c5129` 暗部 → `#d59a4e` 本色 → `#ffd48a` 高光，三层硬边。
- 青绿金属：`#0d3a3a` 暗部 → `#1a6b63` 中间 → `#5be7e5` 边缘光。
- 玻璃/翅膀：深色轮廓 + 30%–60% 透明度膜面 + 2–3 根亮色翅脉。
- 发光核心：暗色外圈 + 亮色中层 + 白点高光 + 低透明度光晕。

## 9. 性能与兼容

- 逻辑画布不超过 480 × 854；更大会让手机端填充率吃紧。
- 每帧只创建必要的对象；渐变、字体、固定数组在初始化时创建。
- 不在每帧 `ctx.save()/restore()` 嵌套超过 3 层。
- 尽量用整数坐标 `fillRect`；路径抗锯齿会破坏像素感。
- 不用 `filter: blur()`、`backdrop-filter` 大面积覆盖。
- Canvas 的 `alpha: false` 可减少合成开销，但需要自己铺满背景。
- 页面切到后台时 `requestAnimationFrame` 会自动暂停；恢复后按真实时间继续，不要累积巨大 `delta`。
- 使用 `prefers-reduced-motion` 时降低闪烁与故障频率，保留主体运动。

## 10. 可访问性与发布

- Canvas 必须有描述性 `aria-label`，例如“机械蜂鸟在夜间植物舱中悬停吸蜜的像素动画”。
- 若整屏是按钮，使用真实 `<button>`，提供 `:focus-visible` 样式。
- 闪烁频率低于 3Hz，亮度变化幅度小于 20%。
- 页面 `<title>` 使用“中文主题 // 英文副标题”格式。
- README 中给出 GIF/截图位置、浏览器要求、许可协议；不要声称支持未测试的浏览器。
- 发布前用手机实际打开一次，检查刘海屏安全区和地址栏收缩后的高度变化。
